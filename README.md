# SimpleExperiment

在 VS Code 中管理一台或多台 Linux Worker 上的实验：配置服务器、同步代码、按 GPU 配额排队、查看任务与日志，并在整批未完成时汇总已经核实的结果。SimpleSFTP 负责实际服务器文件操作。

**当前只使用 Worker。** 启用一台就是单 Worker，启用多台就是多 Worker，统一使用 `worker_pool`。不配置额外控制节点，不把旧控制节点字段补成运行目标；历史格式与明确拒绝的兼容入口保留。

## 能做什么

- 管理多个 PLAN、case 和 seed，保留实际命令、工作目录、执行 Worker、GPU、任务窗口和产物身份。
- 同步所选代码与配置到全部启用 Worker，校验、预演后再提交。
- 同时限制每卡 job 并行数、服务器占卡数和剩余显存，结合自动峰值预算与预留选择合适卡。
- 手动指定一张卡，或选择“该服务器自动派发”并等待该服务器的合适空卡。
- 已进服务器队列的任务由 Worker Scheduler 管理；本机退出不清空它们。
- 按精确任务窗口停止和恢复核实，保留已确认完成任务及产物安全检查。
- 主动查询真实结果，通过内存读取轻量指标并生成本地汇总；弱连接下有限退避重试，整批未知时保留旧表。
- 保留多项目分支、结果对比、TensorBoard、PPT 和 GitHub 等现有入口；科研分析与发布操作由用户明确调用。

## 安装

需要 Windows、VS Code 1.100+，以及每台 Worker 可用的 SSH、Python 3、tmux 和用户准备的实验环境。

1. 安装 [SimpleSFTP 稳定版](https://github.com/zlinkw/SimpleSFTP/releases/latest)。
2. 安装 [SimpleExperiment 稳定版](https://github.com/zlinkw/SimpleExperiment/releases/latest)。
3. 在所有已打开的相关 VS Code 窗口执行 **Developer: Reload Window**。

每个 Release 提供 VSIX 和绑定文件名的 SHA256。也可以使用面板的配套更新入口。插件安装版本属于 VS Code 共用安装；项目服务器配置、队列、运行身份和结果必须保持各自作用域。

## 最短使用路径

1. 用一个窗口打开一个本地项目根目录。
2. 在 **设置 → 服务器** 配置至少一台 Worker：地址、用户、SSH 端口、本机转发端点、远端 Agent 端点、项目父目录、科研环境路径和稳定 ID。
3. 保存并核对 SimpleSFTP 目标，点击 **准备 Agent 并启动**，查看精确目标后确认。
4. 配置代码同步范围，准备 `experiments/plans/*.yaml` 和真实入口。
5. 选择 PLAN，先校验、预演；核对目标、命令、任务数和结果路径，再使用 **校验并提交运行**。
6. 在运行进度查看本机等待、服务器队列、实际运行和产物核实。需要时点击 **更新结果汇总**。

新增第二台 Worker 时重复服务器配置，确保 ID、本机端口和项目路径正确；启用一台或多台不需要切换到另一套架构。后台隐藏 SSH 隧道和手动打开 Xshell 是不同入口，Xshell 保存的密码不能自动供后台连接使用。

首次配置推荐点击“准备 Agent 并启动”，由它协调部署与连接。未打开工作区时执行“准备 Agent 并启动”会直接打开 VS Code 文件夹选择器；先选择真实项目，再核对该项目的服务器与路径。

## 最小 PLAN 示例

下面适用于已经有非交互命令 `tools/build_artifact.py --output <file>` 的项目。替换成自己的真实入口；只管理产物时不需要先改模型或伪造指标。

~~~yaml
suite: build_artifact
mode: train
seeds: [42]
naming:
  output_dir: "work_dirs/{suite}/{case}/seed_{seed}"
runner:
  train_command: 'python tools/build_artifact.py --output "{output_dir}/model.bin"'
  outputs:
    - "{output_dir}/model.bin"
  collect_metrics: false
cases:
  - name: baseline
~~~

需要指标时，声明每 job 独立 `paper.result_csv: "{output_dir}/metrics.csv"`，让真实程序写该文件。不同 seed 不共享一个 CSV。现有参数名不同只改 PLAN 命令；现有程序不能输出指标时再加 [轻量适配入口](docs/experiment-integration.md)。新项目不强制创建旧 simple_project.yaml 或固定双 CSV、四态指标。

## 目录与连接作用域

项目父目录是远端放置项目的父目录。例如本地项目名为 demo_project、父目录为 `/srv/experiments`，最终代码目录是 `/srv/experiments/demo_project`。不要重复追加项目名。安装与状态目录以部署预览为准。

每台 Worker 的本机/远端 Agent 地址和端口动态读取自己的配置，不使用某个固定隧道端口探测所有服务器。面板连接、Conda 与隧道配置按当前项目保存；两个项目窗口不会互写连接。CLI/API 绑定准确项目与实例，窗口切换后旧请求不能借用新项目执行。

## GPU、队列与低流量

当前默认每卡并行 1 个 job，派发前总剩余显存门槛 22 GiB；小显存卡需要按实际任务调整。优先级为逐卡覆盖 → Worker 覆盖 → 项目默认；服务器并发占卡上限对所有 PLAN 合计，0 只暂停新任务。峰值预算与预留检查继续生效，不保证动态任务永远不会 OOM。

低流量模式用于减少重复状态、历史与日志读取，可按需手动刷新。队列推进、必要核实和真实文件同步仍可能通信，不等于绝对零流量。结果更新对短暂网络错误最多尝试三次；写操作不会因为网络失败自动重放。

默认本机代码上传与 Worker 间同步是两个范围。Worker 间默认包含 work_dirs（兼容 work_dir）；每 job 完成只同步其最新产物与当前勾选范围的交集，不自动补回用户取消的范围。原始指标不自动落盘成本机缓存，本地保存最终汇总。

## 结果、停止和安全

任务接收不等于成功。执行状态、退出码、产物完整性、日志异常与指标可汇总性分别核实。已确认完成的精确任务不会因重载或临时断线被随意扣减；新的真实缺失、失败或身份冲突仍会提示。

普通停止绑定 commandId 与实际 tmux 窗口，不关闭整个 tmux server。辅助 Agent 的重启不应被陈旧任务登记永久阻塞。覆盖和清理必须展示精确节点、路径、类型与当前事实，永久删除仍需两次确认；不自动扩大目标，不通过清空内部状态绕过保护。

科研环境和数据协议由消费项目负责。插件不自动安装科研依赖，不隐式执行污染、患者/标签、论文结论或全数据集检查。任务完成与指标存在不等于论文结论已经成立。

## CLI 与 AI 调用

统一入口是 `simpleex --help`。按当前项目选择 `--workspace` 或 `--instance`；先读取准确实例 discovery 与 capabilities/openapi，再调用实时支持的方法。旧的独立 SimpleSFTP CLI 不作为新教程入口。

正式实验先有配置和 PLAN，再通过插件 validatePlan、dryRunPlan 和 runPlan 工作流；不要用直接运行 train.py、临时 SSH、scp 或 rsync 绕过插件。危险动作的 `CONFIRM_REQUIRED` 是正常保护，自动化不能静默填入 confirm/pathConfirmed。

## 多项目分支与工作树

同一个科研仓库常常要并行验证多个想法。这个功能把“一个祖先仓库 + 若干创新分支副本”登记在同一台机器上，让它们各跑各的实验、共用一套 GPU 配额判定，最后只把选中的分支经 PR 合回祖先。入口在面板“实验准备”下方的“项目与分支”卡片。

### 两个概念

| 名称 | 含义 |
| --- | --- |
| 祖先项目 | 本机已有的仓库根（科研主线）。「登记」这一步只往本机登记表写目录、目标分支和 remote，不修改仓库里的任何文件；后面经你单独确认的「创建分支」会在祖先仓库里新建分支和 worktree 目录，PR 合并后的「祖先快进」会更新祖先的工作树。 |
| 创新分支 | 该祖先的另一个独立工作目录（`git worktree` 或独立 clone），有自己的分支、任务队列和产物目录。 |

登记表是本机唯一一份 `%APPDATA%\SimpleExperiment\branch-projects.json`，所有 VS Code 窗口共用。同一目录只能登记一次；登记表损坏时插件拒绝继续读写，也不会覆盖它。

### 登记与创建分支

1. 点 **登记祖先项目**，选择含 `.git` 的仓库根。弹窗列出目录、当前分支、HEAD 和有没有未提交修改，确认后才写入登记。非 Git 仓库、`detached HEAD` 或读不到 Git 状态会被拒绝。
2. 创新分支有两条路：
   - **从祖先创建分支**：填分支名：必须以英文字母或数字开头，其余字符只能是字母、数字与 `. _ - /`，不能含 `..` 或 `//`，不能以 `/` 结尾；再选存放父目录。预览列出祖先目录、新分支、基点提交、将要新建的目录（必须尚不存在）以及将执行的 `git worktree add <新目录> -b <新分支> <基点>`。确认后才创建；同名分支或已存在目录一律拒绝，不覆盖。祖先当前有未提交修改时，新分支只从已提交的基点创建，不会把未提交内容带过去。
   - **登记分支副本**：已经自己用 `git worktree` 或 `clone` 建好的目录，选择所属祖先和目录后确认，只登记归属，不合并、不移动提交。
3. **刷新状态** 只读重读每个登记的真实 Git 状态：已验证、目录缺失、不是Git仓库、身份漂移（实际 Git 根或分支与登记不符）、有未提交修改、detached HEAD、读取失败。分支还显示与祖先的关系：与祖先同点、领先祖先、已分叉、独立仓库（关系未证明）、关系未知。科研验证不在这里自动执行，需要在该分支窗口自己跑计划和门禁。
4. 每行的 **打开** 在新窗口打开该项目（独立实例），当前窗口的工作区不变；当前窗口已经是该项目时只提示，不重复开。
5. **移除登记** 只删除插件内的登记记录，不删目录、分支、worktree 或提交，之后可以重新登记。祖先下面还有分支登记时会先拒绝，需要你逐个移除分支登记后再移除祖先。

### 多分支并行运行

- **刷新统一策略**：把当前窗口的 GPU 配额设置（每卡任务数、最低空闲显存、并发卡上限）保存为本机统一策略快照。预览逐台列出“新增 / 更新 / 保持 / 保留”，只替换本窗口核实过的服务器，其它窗口登记且冲突的条目保留原值。登记或移除项目后插件会自动补一次快照，失败只写进操作日志，不会吞掉登记结果。
- 统一区块逐个已登记项目显示 **待派发 / 运行中 / 待核实** 和阻塞原因，并标记 **已打开(握手确认)** 或 **未确认打开**。是否打开只认实时握手，遗留的旧实例记录不算打开。
- 每行的 **提交运行**：选择该分支项目里的 PLAN，由该分支窗口自己判定能否直接提交；确认后任务进入该项目自己的持久队列，产物冲突等确认仍在该分支窗口弹出。当前窗口不代为准备环境，也不做任何 Git 写操作。目标必须是已登记项目根，插件不按面板传来的路径猜测；分支窗口未打开或不可达时直接拒绝并说明原因。
- 并行只在既有 GPU 配额允许时发生。配额已满时该任务本轮不发送，也不会挤掉已经在占卡的作业；它带着“统一派发等待配额”的原因留在原队列，后续调度可以用同一个命令身份重新申请名额。只有“提交结果未知”时才绝不自动重发，以免重复提交。
- **刷新运行状态**：逐个已登记项目做真实握手并拉取最近操作记录；没刷新过的一律不猜。
- 统一派发只在“已登记项目不少于两个、且当前窗口自身也在登记内”时生效；只有一个项目时仍走原来的单项目流程。

### 结果对比与 HEAD 核对

- **结果对比与选优** 读取本机各登记项目的队列记录，逐个 PLAN 显示计划文件名、已确证作业数／作业总数、运行中、待核实、等待（有失败或中止时一并显示），以及该 PLAN 的运行来源分支与提交（当时有未提交修改、或当时脏状态未知时会标注，干净时不标注）和有没有已验源码清单。它只列事实，不替你做科研优劣判断。
- **核对HEAD** 只读地把当前提交树中“已验源码清单”覆盖到的文件逐个比对字节（类型、大小、内容 SHA），并同时显示该 PLAN 的运行来源提交，与当前 HEAD 不同会明确标出。它只证明清单内的源码与配置跟已验字节一致：不覆盖整仓，不含数据、权重和仓外输入，不证明这批结果的实际运行就出自当前 HEAD，也不代表科研运行已完成或科研结论等价。清单里没有的依赖（被 Git 忽略或未跟踪的文件）算无法证明，插件不会代为提交来凑证明。

### 科研 PR 与祖先快进

推送与合并是两步，各自需要单独确认：

1. **创建PR** 前需要在该项目里选定一个或多个 PLAN（可多选，插件不自动判优），并满足：该 PLAN 的作业全部完成确证、当前 HEAD 逐文件等于已验清单、工作树干净。预览显示合并目标（登记祖先的真实 origin，凭证已剥离）、目标分支、来源分支与完整提交、既有 PR 状态以及相对基线的领先/落后。推送只允许普通快推，不 force；确认后每次真正写入前还会重读队列和身份重跑同一校验，撤证、版本或命令变化立即零写入停止。`gh` 未安装或未登录时如实失败，插件不代装代登。
2. **合并PR** 只在存在“远端头等于本机 HEAD”的开放 PR 时执行，并使用 `--merge` 加 match-head 约束；远端头一旦变化 GitHub 会拒绝，不会盲合，也不使用管理员权限。合并同样是不可逆的远端写入：需要你重新选择 PLAN，并重新满足同一候选门禁（该 PLAN 作业全部完成确证、HEAD 逐文件等于已验清单、工作树干净），确认后、真正发送前还会再复核一次，撤证或版本变化就零发送。结果未知时绝不重放，再次点击只做只读对账；PR 已经在网页被合并的走只读恢复，核对通过后才取真实合并提交，不重发合并指令。
3. 确认真实合并之后，才会经你**再次单独确认**尝试更新本机祖先：祖先必须干净、正处在目标分支、真实 origin 仍与登记时的祖先地址一致、远端确实包含该合并提交、且本机 HEAD 是该远端目标的祖先，才 `ff-only` 快进，不产生合并提交；任一条件不满足都会明确说明“未更新”。合并后主线仍需按流程重新验证，之前的候选验证不自动等于主线已验证。

### 边界

- 不 reset、rebase、stash、强推、删除，也不代为 stage/commit。
- 不修改你的 Git 配置和 `.gitignore`。`simple_cluster/state/` 产生的未提交记录由你按仓库自身规则排除，插件不会把整个 `simple_cluster/` 忽略掉。
- 登记、创建分支 worktree、移除登记与派发同意都走同一项本机共享资源，避免两个窗口同时改登记或同时发卡。

### 常见提示

| 提示 | 怎么处理 |
| --- | --- |
| 该分支项目未打开或实例不可达 | 先在卡片上点 **打开** 打开该分支窗口，再重试提交或刷新。 |
| 工作区 …… 实际存在 N 个存活实例 | 同一项目被多个窗口打开。面板操作请关掉多余窗口后重试，面板提交不能指定实例；使用命令行时可以把错误信息里给出的完整 `--instance <pid:startedAt>` 传给该命令。 |
| 目录 X 已登记为 Y；同一目录不能重复登记 | 先移除旧登记，或换另一个目录。 |
| branch-projects.json 内容损坏 | 不要手工覆盖该文件；先人工核对内容再处理，在此之前插件不写登记。 |
| 服务器 X 的配额策略与当前配置已变化 | 点 **刷新统一策略** 重新登记快照。 |

## 常见问题与更多说明

空卡不派发、端口可连但项目身份错误、Conda 缺依赖、跨窗口实例冲突、ACTIVE_TRANSFER 恢复、弱网结果更新及产物覆盖，见 [完整说明的常见问题](docs/simple-experiment-setup.md#13-常见问题)。所有字段、默认值和历史参数状态见 [配置字段参考](docs/configuration-reference.md)。

开发流程中 `npm run package` 只构建和打包，`npm run install:latest` 才显式安装一次新版本；源码推送、稳定 Release、本机安装和远端 Agent 更新是独立状态。纯文档修改不发布空运行版本。详见 [交付说明](docs/release-delivery.md)。
