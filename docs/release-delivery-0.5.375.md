# 0.5.375 索引完成状态和本机发布等待修复

## 原因及实现

0.5.374 页面在查询完成后设置固定 30 秒计时器，将所有已完成位置改为未完成，并清空文件状态。索引是否已建立与某一轮查询的时效被混为一谈。0.5.375 保留完成状态及明确标注的上次读取/校验时间；超过观察窗口后的展开、切换模式和手动刷新主动请求新轮次。实际文件变更通知仍使旧观察失效，旧回包不能恢复它；不把失败、尚未查完或旧清单当作确认缺失。

此前现场性能报告只覆盖基础扫描器，没有覆盖 ProjectFileIndex 诊断目录落盘等待。完整本机读取链路的首次/重载读取会等待约 1932 个目录 JSON 写入。现在仅对页面 local.metadata/agent.metadata 的诊断文件后台落盘，已主动核实的文件系统状态先发布；加速基线及服务器游标仍先核实。后台写入继续使用原串行队列、8 路分片写入、owner 校验及根文件最后发布；连接换代取消旧 owner 写入时不误报持久化故障。

其他读取即使带后台标记也不进入此例外，PLAN、产物、清理和文件操作保留实际读取及原 reading 落盘边界。文件操作前后刷新、删除增量、重新创建、重载恢复和失效隔离不变。
