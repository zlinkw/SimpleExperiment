## 2. 产品目标与使用流程

用户要方便地把实验派到服务器上运行，查看进度、日志和产物，不需要手动执行代码。插件管理项目和进程；AI 理解科研项目、撰写代码及命令、分析结果。

主线项目窗口管理登记的主线及全部分支副本 → AI 编写代码/参数/PLAN → 用户或 AI 明确选择分支和 PLAN 提交 → 插件必要校验、同步、GPU排队及启动 → 插件记录真实运行状态/退出码/日志/产物位置 → 结束通知 AI → AI 分析并生成报告。后续实验仅在既有明确授权内继续。

实施以当前完整面板及其 Host/运行时为功能全集，不能只看 MCP。先精简插件本体，再对齐、补齐 MCP。默认面板走 src/ui/PanelHtml.ts 委托的 legacy 实现；模块化 Section 不是当前功能全集。不附带迁移整套 UI 架构。

## 3. 已确定的边界

### 3.1 主线统一管理分支

- 一个管理窗口即可，分支窗口关闭也能登记、查看、提交、查询、停止和清理。用户在不同时间可以切换不同项目并连接相同服务器。
- 管理入口仅操作明确登记的所属项目/分支；每项操作绑定其项目根、远端根、PLAN、队列、环境和同步范围，不临时改全局工作区来模拟分支执行。
- 默认提交明确选中的分支、PLAN和任务；“全部运行”是显式范围选择，不因登记自动启动。
- 每个分支使用独立远端代码和输出目录。共享数据和环境须明确配置；不得同步主线代码覆盖分支。
- 现有 BranchProjectService 继续负责登记和 worktree 创建。BranchPlanDispatch 当前依赖目标窗口握手，须改为主线 Host 对明确分支上下文调用现有执行链，不新增多个窗口间的调度系统。

### 3.2 PLAN最小契约

PLAN保留为实验意图、任务声明和产物归属入口，至少有稳定标识、名称/简短目的、实际启动命令、独立输出目录。工作目录可继承分支根；参数组合及必要产物声明可选；环境/Worker/GPU/资源要求继承项目设置，必要时覆盖。

AI填写任意适合项目的真实命令，插件展开后执行。取消强制wrapper、adapter、科研YAML结构、train/test/train_test、指标CSV、checkpoint和科研日志格式；插件不推断Python参数、不改写消费项目科研配置。

插件自动记录项目/分支、PLAN提交版本、实际命令、已有代码来源身份、Worker/GPU、commandId、真实窗口、时间、退出码和产物路径。提交时确定启动输入，执行端不再重新解释科研PLAN推导另一套命令。复用已有输入保存，不另建通用任务数据库或证明链。

执行结束、声明产物状态、科研成功与否分别表达。AI报告模板只要求目的、实际运行、证据文件、观察、失败与未知；插件提供模板和文件入口，不解析或审核科研结论。

### 3.3 多电脑共用服务器

允许不同电脑使用同一SSH账号、不同项目目录。复用项目队列、tmux和资源采样，只补避免误操作与GPU抢占的必要隔离：

- 项目目录、输出、状态、Agent/Scheduler身份及窗口、任务控制归属不串用；连接资料可以复用，项目设置不意外全局覆盖。
- 停止绑定原commandId、项目、服务器与真实窗口，保留取消围栏；不按前缀、整个tmux会话或PID停止。
- GPU以实际服务器及设备身份协调，不能把各客户端自定义Worker标签当不同物理资源。共享采样不等于共享预约。
- 在服务器最终准入处短暂串行完成占用检查与预约，复用原生任务窗口资源事实；各项目仍保留独立队列，不建租户、用户角色、统一任务库、公平调度或中央队列。
- 同SSH账号拥有相同系统权限，上述是防误操作隔离，不承诺阻挡账号使用者在插件外执行任意命令。

### 3.4 新版本任务

用户明确取消旧任务/旧版本自动兼容要求。新实现只支持新任务；不继续做旧协议迁移、旧字段补全或旧结果继承。旧格式明确提示不支持。旧文件/记录/产物保留，不自动转换、重派、重跑或删除。不能为旧功能兼容阻塞新计划，也不能把旧结果标成新版本已通过。

## 5. 分支删除与合并后清理（面板与MCP同一实现）

### 5.1 主动删除

用户或AI发起预览 → 从登记/配置及运行关联解析本机副本和各服务器实际分支目录 → 主动查询真实存在性/类型/影响 → 展示完整节点和绝对路径、未提交修改/活动任务、未知或失败位置 → 用户按现有两页路径审核确认 → 直接永久删除确认目录并正确收尾worktree登记 → 逐位置确认结果 → 全部目标确认不存在后完成分支登记收尾。

- 本机和服务器目录包含其内代码和产物；不另建备份/隔离副本。失败不能假成功；保留剩余清理所需最小登记及原请求，未知不得盲重发破坏操作。
- 本地Git分支引用、GitHub远端分支分别是明确选项，默认不勾选。目录清理为所选分支移除的主体，不把远端服务器目录混同Git远端引用。
- 用户已明确允许：登记分支存在未提交修改时，清楚展示后仍可确认永久删除。此例外仅该整体删除入口，不扩大到其他dirty文件清理。
- 用户已明确允许删除登记分支副本根，须对原“禁止删除项目根”作此精确例外；祖先根、仓库共享对象、其他分支、共享数据/环境和机器状态继续保护。安全根应是经核实可管理该副本的容器/父级，不能把待删目录本身充当安全根。
- worktree须按Git元数据关系正确解除登记/收尾，不能只删文件夹留下失效引用，也不能误删祖先.git或共享对象。具体执行复用可用Git能力和精确清理器，不用宽泛force命令绕保护。
- 目录外产物和非分支专属目录不自动加入，必要时作为明确独立目标重新审核。远端目标须核实host及安全根，不能从名字/旧示例猜路径。
- 活动任务只作影响提示，不凭历史登记阻断用户确认的精确删除；可由用户另行明确选择先停止该分支任务。删除不隐含停止授权。
- 保留永久删除两页完整路径确认、固定类型/指纹/链接越界防护、规范安全根/直接父目录验证、成功cd及物理cwd核对、仅./直接子项执行和删除后主动核实。目标实际变化重新确认，不因无关遥测/队列/日志变化失效。
- 本计划只授权实现此功能，不授权现在删除任何本机或服务器真实目录、Git引用。

### 5.2 合并后清理

AI通过标准Git/gh等完成合并并核实真实成功 → 调用同一分支清理预览 → 插件展示删除范围及选择 → 取消则保留，确认则执行上述两页审核后的同一删除流程。

合并失败/结果未知不能伪装已合并。保留独立主动删除入口。无需为提示清理重新引入自动合并系统、后台GitHub轮询或另一套清理服务。

### 5.3 全部删除与清理的后台隔离（用户2026-11-24补充）

所有删除、自动清理及相关收尾统一在后台执行，适用于本机、服务器、分支、文件/目录、隔离区、空目录、日志/缓存及同步覆盖清理。独立目标可并行推进；清理耗时、查询失败或某个请求未结束，均不得成为其他功能启动、运行或交互的等待条件。此要求不恢复已退役或已取消的自动清理，也不新增真实删除授权。

- 完成原有必要预览及人审后及时返回明确请求身份；接受请求不等于删除成功。状态、进度、失败及可继续入口在原有操作视图可查，正常运行不抢焦点、不弹阻塞进度窗；必要路径确认和真实失败提示保留，不吞错或伪造完成。
- 不将清理Promise、全局busy标记、共享队列锁或同步文件/进程调用串到插件启动、连接准备、校验、提交、调度、停止、观测、同步、TensorBoard或面板/MCP其他操作上。不以等待后台清理完成换取这些功能可用；复用现有异步执行和操作登记，不另建通用后台框架。
- 互斥仅覆盖同一实际目标及重叠路径的真实读写冲突，必要共享元数据短暂更新后释放；不把项目、Worker、连接或整个Host锁到删除结束。冲突请求及时显示精确目标及原因，不能全局排队卡住；未知破坏性请求继续保留防重复执行保护，独立目标照常运行。
- 并行目标各自执行完整路径安全、固定类型、父目录/cd/物理cwd及./直接子项检查；按既有规则处理安全失败和部分结果。后台化不绕过双确认，不自动停止任务，不删除仍未获授权的对象。
- 使用受控未完成Promise/假清理器验证：清理尚未完成时无关功能已能进入实际处理，独立清理能并行，同目标不重复执行，拒绝/失败可见且不留下全局阻塞。此为正确性回归，不新增压测、计时阈值或放宽现有测试期限。

## 6. TensorBoard保留与解耦

用户最新决定覆盖早先“全部移除TensorBoard”建议：保留独立可选可视化，不恢复通用科研结果引擎。

- 原生TensorBoard启停、状态、代理、原生页面和用户显示设置保留；需要实际TensorBoard环境、event日志目录与正常连接，不自动安装依赖。
- 插件自定义标量曲线也保留，但当前是自行解析event而非直接原生页面：src/clusterAgentRuntime.legacy.ts的scalar_catalog调用Scheduler展开PLAN、假定output_dir/tb_logs；extension/legacy.ts的scalarViewerQuery按PLAN/case/seed聚合，ScalarAggregation.ts按seed去重/均值/标准差。
- 解除固定科研PLAN、tb_logs命名及训练模式依赖，按明确日志目录/run/tag查看；跨run/seed聚合必须有明确分组关联，不猜科研结构。缺少关联时分别展示，不静默误聚合。
- 不承诺所有TensorBoard编码都能由当前自写解析器处理；保留可见错误和原生查看路径。优先复用现有解析/展示，不另写通用指标框架。
- 查看/聚合/TensorBoard未安装或无日志均不得成为运行准备、提交、完成状态或普通产物传输门槛。
- tensorboard_status/start/stop/viewer及必要端口、logdir设置保留，按目标分支和服务归属精确操作。
