# PLAN 提交与实时显卡状态

运行 PLAN 的本机代码上传与 job 完成后的 Worker 产物复制分别处理。产物复制不占用整个项目的代码同步门禁，不取消正在进行的复制，也不阻止其他 PLAN 完成校验、确认和提交。默认代码范围排除 work_dirs 和 work_dir。用户显式把产物路径纳入代码范围时，重叠范围不能同时自动复制。

产物复制只在内存保存正在传输的精确相对路径。清理、覆盖和文件树写入若与这批路径重叠，在执行边界提示重试；其他 job 路径不受这批复制影响。删除仍使用原有完整路径双确认、直接父目录和 SimpleSFTP 防护。

Worker 的 /api/gpu 从显卡实际查询获取数据，HTTP 与采样线程合并同一秒内的请求，仅在内存复用。不读取旧 gpu_snapshot.json 判断当前显卡，也不根据历史任务登记降低采样频率。正常采样间隔约一秒，实际延迟包含 nvidia-smi 查询和隧道时间，不能保证硬实时。任务快照读取使用独立线程，不阻塞显卡采样。GPU 历史按原分钟粒度保留，失败样本明确标记 degraded。

隧道仍使用当前 Worker 配置的端点和现有 SSE/WebSocket 通道。事件带实际采样时间，迟到事件不能覆盖较新的直接查询。本轮验证包含运行入口、传输并行、重叠路径保护、GPU 并发查询、失败恢复和流式 UI 数据源；生产显卡刷新需用户重载插件并更新 Worker Agent 后验收。开发未更新远端服务或操作科研任务。
