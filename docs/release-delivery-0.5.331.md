# 0.5.331 主动查询完成判定与独立状态展示

## 最终行为

客户端与 Worker 统一依据本轮 Scheduler/tmux 观测、当前运行的最终 artifact manifest 和实际声明文件判定。执行状态、结果状态分别提供给面板与 API；CLI 使用同一接口。历史完成标签、旧错误及磁盘快照不裁决当前状态，身份不符或查询失败时返回未知，不重复启动。

窗口仍在排队、启动或运行时保留相应执行状态；未知的窗口阶段不能因产物完整提前显示完成。窗口结束且退出码未知时不判失败；清单属于当前 commandId、任务和模式，声明的必要产物为真实非空文件且已核实时才确认结果完整。明确非零退出始终显示执行失败，即使结果完整；窗口关闭后仍能通过真实结果确认完成。清单不存在、不可读、身份或模式不符、文件缺失、空文件及已有 fileStats 不匹配分别显示不完整、待核实或与本次任务不符。只进行相关文件的元数据检查，不加载权重，不增加科研环境或数据核验。

检查还补齐了三处遗漏：真实面板的数据投影原先未传递 executionState/resultState；渲染签名未包含独立结果变化；补跑入口依赖 Worker 的旧完成标签。现在面板以中文独立显示执行与结果，结果变化可以触发刷新，状态行独占一行。仅补跑通过同一客户端判定核对实时任务，并重用同次窗口查询排除活动执行和同一运行的明确非零退出，完整的其他副本不能掩盖这些证据。无身份清单不作为可信完成结果。
