# 运行异常与完成状态

0.5.337 将执行、产物与异常证据分开。旧实现仅根据 tmux 退出状态及最终产物清单得出 completed，未处理退出码为零时的 ctypes 回调等异常，因此完成训练并不等于运行无异常。

## 当前协议

`executionState` 与真实 `exitCode` 描述进程；`resultState` 描述本轮实际产物；`runtimeDiagnostics` 描述本次 commandId/runId 的原始控制台日志。明确非零退出仍为 failed，即使产物完整。为兼容现有终态控制，`status=completed` 保留其执行结束且产物完整的含义，消费者必须结合 `completionState` 或 `successful` 判断无异常成功。

| completionState | 含义 | 展示及汇总 |
|---|---|---|
| verified | 完整原始日志扫描结束，未检出受支持的异常块 | 无异常成功计数；正式表 |
| review_required | 检出运行异常 | 完成但有异常，待复核；待复核表 |
| unverified | 日志缺失、不匹配、读取失败、尚未扫完或执行尚未结束 | 运行日志待核实；待复核表 |

执行失败不会把实际完整的声明产物改成“不完整”，有效指标仍可进入待复核表。旧清单只有 failed 文本而没有真实退出码时，不推断非零退出，也不计入无异常成功。通用清单校验入口仍默认要求 completed；仅只读结果收集明确允许核验失败执行留下的完整产物，不放宽启动、覆盖或恢复边界。

“未检出异常”仅指本解析器支持的结构化异常模式，不是对所有运行行为或科研指标正确性的保证。普通警告、零预测指标、进度条及正常 nvJitLink 提示不属于异常。所有有效数值，包括零，继续保留；异常不自动判定指标无效。

## 原始证据

Agent 在既有 commandId 专属 console.log 写入开始标记；Scheduler 在原始输出流标记 train/test 阶段和结束，并将摘要及日志绑定写入既有最终 artifact manifest。没有新增异常状态文件。作业仍是原来的前台进程树，命令、环境、训练及测试逻辑不变。

主动查询以当前原始日志为准，不把清单中的旧摘要当作当前无异常证明。解析游标、分块缓冲及去重仅在内存；断线或 Agent 重启可重新读取原始文件。UTF-8 和 ANSI 在完整日志行上解析，位置保留原始字节及行范围。事件按 commandId、日志路径和起始字节绑定，相同位置重复读取不增加次数，不同位置的重复异常计入次数。

每轮每任务最多读取 4 MiB，后续主动查询继续。缓存至多 256 个任务；所有异常计入总数、类型和阶段统计，接口保留前 100 个摘要与原文范围，更多事件通过 `truncatedExceptions` 明示。摘要最多 4000 字符，完整原文始终留在原日志中。日志缩短、替换或已结束日志修改会重新分析。未完整读取时不声明无异常。

## 历史与复核入口

0.5.338 修复旧任务被统一标成待核实的问题。当前主动查询中的已结束任务，即使旧日志没有新版标记，也会自动分块分析 commandId 对应的唯一原始日志；不扫描历史目录，不读旧状态记录，不要求逐项点击。正常完整日志归为已完成，检出异常归为完成但有异常，待复核。没有取得完整日志证据时仍显示未核实，不能直接当作无异常成功。

自动兼容只接受当前项目内按 commandId 计算的精确控制台日志路径。任意旧登记路径不能获得此兼容；有新版标记的日志仍严格按标记隔离命令。Agent 重启后重新主动读取，无需保留授权状态。运行中的旧任务不据此宣称日志已完整核实。

用户仍可点击 job 的“重新分析运行日志”，或调用只读 `tasks.analyze` / `simpleex task analyze`：

```
simpleex task analyze --workflow WORKFLOW_ID --index 0 --json
simpleex task analyze --worker WORKER_ID --command COMMAND_ID --output work_dirs/job --json
```

重新分析核对 commandId 专属日志路径，主动重读并返回真实退出码、异常类型、次数、阶段、摘要和日志位置；不改写历史任务或旧产物清单。旧 Worker 不具备 runtimeDiagnostics=1 时明确要求更新，不将缺失能力解释为无异常。

## 结果

UI、API、任务计数和 PLAN 状态不将异常或未核实日志计为无异常成功。实时结果收集仍保留可核实的有效指标。正式表仅包含完整产物、未明确非零退出且日志已完整核实无异常的 job；其余有效指标放入带明确提示的 `review/` CSV 与 Markdown，列在同一个最新汇总 JSON 中。统计公式不变，不补零、不自动重跑、不删除任何日志、指标或权重。

本机升级不改动正在执行的远端任务。新任务的阶段标记需要用户更新匹配 Agent/Scheduler 后产生；已有任务只能主动分析现有日志。开发验证仅使用合成日志和隔离 CPU/tmux 夹具。
