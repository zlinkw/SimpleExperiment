# 最新结果汇总

从 0.5.333 起，普通结果汇总仅依赖当前 PLAN、服务器实际 tmux 窗口和最终产物。旧结果注册表、同步账本、任务历史、目录索引及发布恢复日志不参与结果发现、完成判断或指标回填。本说明取代旧文档中普通汇总依赖历史 registry、attempt 和原始文件缓存的要求。

## 数据路径

1. 读取当前项目的非归档 PLAN。通过一台可访问 Worker 的纯展开取得 job 声明，并核对其 PLAN 哈希与本机实际文件一致。无写入、同步或科研校验。
2. 向全部启用 Worker 查询声明路径及相关实际 tmux 窗口。结果专用查询不读取任务队列、清理记录或哈希缓存数据库。只对清单和声明指标计算实时哈希；权重仅核对路径、类型、存在及声明大小，不读其内容。
3. 通过现有 SimpleSFTP 内存下载协议读取最终清单和声明指标。核对执行身份、job、模式、路径、大小及 SHA256。相同副本只计一次，身份或内容冲突不按时间戳挑选。
4. 在内存使用原有指标别名、分组、派生指标、均值及样本标准差公式。部分结果也生成表格，标明实际/预期 seed 数；单 seed 标准差留空，不补零、不使用上一次数据。

自动汇总由主动查询得到的完整产物触发，不依赖完成事件或持久化完成标记。打开结果页会主动查询一次；手动更新始终重新查询。只读观测期间不修改、重跑、停止任务，也不更新远端服务。

## 最终输出

仅保存结果目录内的 `latest-results.json` 和当前 CSV/Markdown。JSON 包含生成时间、job 覆盖情况、必要来源信息和已生成表格，不保存原始文件、逐行源数据或下次查询的执行状态。JSON 不是服务器状态来源。

JSON 用固定暂存槽原子替换，然后分别原子写入表格；没有整批回滚日志或历史备份。同进程请求在内存串行，多窗口写入用进程退出即释放的内核 IPC 协调，不读取或创建租约 JSON、锁文件及 PID 记录。中断时重新从完整 JSON 生成表格，不恢复旧事务。打开表格前会重新生成，避免打开上一批残留内容。目录展示只使用 JSON 声明的表格，不扫描旧目录补回结果。既有未列入的文件不自动删除。

全部查询失败时保留原导出文件，界面明确标为非本轮结果；本轮结果行为空。已确认不存在的目标退出本轮结果。全部目标确认不存在时发布空结果，旧表不再出现在当前目录展示中。

UI、`results.list` 和 CLI 共享这一查询与汇总服务，`results.list` 返回 `source=active_query`、本轮时间及覆盖情况。原结果入口保留兼容。普通 job 产物同步仍遵守原勾选范围，与本机汇总独立执行。

## 兼容与验证

需要 Worker 的 `resultCollection=1` 能力，以及 SimpleSFTP 的内存 wrapper 读取能力。旧 Worker 明确提示更新 Agent/Scheduler，不退回旧状态文件。发布和本机安装不自动部署远端。

回归包括真实文件系统上的最终清单、复制后 inode 变化、逐项非法查询隔离、权重零内容读取、部分汇总、重复副本、身份/内容冲突、删除、断线、自动完成、重复请求和单文件原子写入中断。开发使用临时夹具，不处理真实产物。实机入口验收需用户重载并更新 Worker 后执行。
