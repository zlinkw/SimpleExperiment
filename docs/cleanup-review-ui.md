# 清理审核界面 0.5.307

历史清理记录载入后，界面原先无条件关闭确认和执行按钮。即使记录处于 ready、文件审核通过且等待确认，也无法继续。本次统一预览、路径确认和历史记录载入后的按钮判定：未确认、已确认一次和已确认两次，分别进入对应步骤。加载记录不执行删除，不自动补齐确认次数。

主要流程改为“审核文件 → 确认完整路径 → 删除已确认文件”。永久删除仍要求同一批完整路径两次确认。文件路径和处理方式直接显示，关联依据、校验值、文件明细与恢复功能折叠展示。删除不再显示一个并不会使用的 clean_dir 目标位置。“幂等恢复”等按钮改为“继续删除剩余文件”“刷新清理状态”“重新审核剩余文件”。

过期、已有后续操作、审核受阻或已经完成的记录不开放删除，显示具体原因或重新审核入口。选择变化会清除当前确认；恢复、移走和删除保持各自的确认规则。后端指纹、活动任务、安全根、直接父目录及最短子路径保护保持原样。

本地验证：

- `planCleanupPanelBridge.test.js`：17 项通过；先复现历史记录按钮锁死，再覆盖历史记录的 0/1/2 次确认、刷新后继续确认、过期和已有后续操作、选择变化后的失效、按钮文案及执行响应丢失后的主动查询。
- `planCleanup.test.js`：30 项通过，包括永久删除双确认、文件变化、共享目标保护及实际渲染脚本语法。旧脚本测试补齐真实服务返回的 ready 状态。
- 隔离的 headless Chromium 页面：载入历史删除记录，分别点击两次确认，第一次后删除仍禁用，第二次后删除可用；检查无脚本错误。仅使用合成路径，未点击最终删除按钮。

验证过程保留两项修正记录：首次 package 被编译 runtime 常量仍为旧版本的闭包检查拒绝，源常量同步后重新编译；随后一次既有 independentAgent 登录 shell 测试遇到本机 WSL 子进程 10 秒超时。最小 WSL 存活检查成功后，同一测试单文件复核 4 项通过，真实 shell 用例约 431 毫秒。未修改 Agent 生产逻辑、放宽超时或跳过该项检查。

版本发布使用仓库的完整 package/build、面板脚本、串行回归与 VSIX 验证流程。未调用真实清理 API、修改科研文件、连接 Worker 或启动训练。安装后的实际插件界面仍需用户重载窗口后验收。此版本不修改 Agent/Scheduler 行为；runtime 只随包同步版本常量，不要求为本次界面修复单独更新远端。
