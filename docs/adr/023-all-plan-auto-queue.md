# 全部计划使用自动排队

“运行全部计划”曾绕开普通提交链路，逐个要求选择 Worker，再把整个 Plan 直接交给旧调度入口。该行为与正式 job 自动队列不一致。

全部与所选入口共用一个批次锁。全部入口在锁内刷新本机计划元数据，冻结当前计划路径，规范化去重并检查自动队列能力。空目录、无效路径或不支持自动排队时整批不提交，不回退到手选服务器。显式空选择仍然报错，不扩大为全部。

每个 Plan 通过普通 runPlan 链路检查当前配置、拓扑、Worker 项目、同步代码、校验与预演，并保留实际产物覆盖确认。自动选择的校验 Worker 不限制后续 job 的调度范围；空闲 GPU 为零时任务保持排队，资源可用后按现有调度策略派给已启用 Worker。

批次不继承按钮载荷中的旧服务器选择。取消、失败、未知回执或切换项目/服务器后停止后续提交，保留已接收计划及未提交清单，不自动重复执行。全部入口向 UI 返回真实批次结果，避免把部分失败标成完成。

定向验证覆盖真实消息路由、自动主节点选择与队列分配、无空闲 GPU、重复点击、全部与所选入口互斥、失效路径、工作区切换和部分失败。科研 Plan 未实际运行，远端 Agent 未部署；安装后等待用户重载窗口验收。

## 同版本批量并发提交

两个批量入口按每轮最多四个 Plan 并发准备、校验和入队。每轮等待所有已发起项结束，再统一触发派发；出现失败、取消或未知回执后不启动下一轮，成功入队项继续保留。批次锁会等待实际共享工作及确认操作退出，不因外层取消提前释放。

批次开始固定代码指纹和 Plan revision。全部 Worker 的代码同步、接入规则同步、SimpleSFTP 准备和 Git 版本查询各只做一次；每个 Plan 仍有独立操作身份及唯一来源记录文件。元数据重复读取按 Plan 合并。共享结果只在当前内存批次生效，结束、重载或项目切换后不可复用。

同一代码版本不能证明不同 Plan 的任务声明相同。每个 Plan 仍独立展开任务并校验配置、种子、模式和输出路径，使用既有结构缓存；提交路径复用校验展开结果进行逐 job 预演，不额外请求重复远端预演。每个 Plan 的服务器任务与当前产物仍主动查询。入队前重新读取该 Plan 原文并核对 SHA256，同时增量核对代码指纹，防止混用校验结果或提交过期配置。

覆盖确认及对应文件处理保持串行，保留精确路径、双确认和直接父目录安全规则；队列接纳保持串行，随后四个 Plan 共用一次派发轮次，避免旧快照覆盖和重叠输出路径竞态。其他校验工作并发执行，不改变 GPU 调度策略。
