# 低流量模式的后台通信

低流量开关仍是本机全局偏好，普通模式沿用原有请求和刷新路径。低流量模式不自动刷新 GPU 历史、终端列表和终端日志等展示内容；用户可以手动刷新。

自动排队仍需当前执行窗口与显存证据，不能完全停止所有通信。运行中的 job 只跟踪执行状态，不反复读取其结果清单和运行日志；真实退出、窗口缺失或状态不明时再做必要的产物与日志核实。手动详情刷新保持完整查询。完成确认、显存预算、精确停止、产物同步与安全审核不由显示开关绕过。

执行库存已经携带有效 GPU 采样时，同一轮派发复用该原始样本，不再立即单独查询一次 GPU。复用最多接受 5 秒内且同一连接代际的样本，不刷新采样时间；过期、缺失、异常、连接变化或显式手动刷新仍读取服务器。全部声明 job 已确认完成且没有继续提交或停止意图时，结束该批次空闲显卡轮询；已有产物同步处理入口保留。

低流量 HTTP 请求显式携带压缩偏好，新版 Agent 对可节省空间的 JSON 响应使用 gzip，保留状态码和原始内容；小响应与旧 Agent 返回普通 JSON 仍可读取。普通模式、文件字节下载和 SSE 内容不被该策略改写。解压后的响应继续经过原有大小边界。`panel.diagnostics` 的进度证据同时记录解码后大小、HTTP 响应体传输大小和编码方式；这些字节不包含 SSH、TCP 等协议开销，也不代表整台机器的计费总量。

验证使用个人、单 Worker、约 72 个 job 的正常响应样例，检查请求选择、JSON 完整性、gzip 协商、过期采样和完成确认；没有新增压测或速度门槛。实际半小时流量应在更新并重载、Worker Agent 更新后观察，不能用样例压缩量代替实测计费流量。
