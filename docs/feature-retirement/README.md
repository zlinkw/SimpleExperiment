### 证据、验证与普通失败分支

每项从实际当前渲染控件追到处理函数及项目/Worker/任务/结果绑定，记录入口位置和对象、实际动作、可观察最终效果、源码候选/宿主身份与原证据定位。截图/工具记录用既有机制，不另造长报告；取消、打开选择器、进入确认页、请求接收或仅静态可达都不记完整执行通过。命令面板、GUI、MCP/CLI分别统计；一个位置的通过不覆盖同命令的其他真实位置。

覆盖表分开保存源码来源数、当前真实可达入口/渲染实例数、当前实点通过、当前preview、历史证据、当前失败、尚可执行未测、本人、具体外部条件、暂缓、兼容无producer和selector。动态模板与当前实例关系可追溯，不能把模板命中数当唯一按钮数，亦不能把无producer改成退役。历史证据不自动提升为现版实点：只有同一最终候选和对象链条已有真实操作证据仍有效时才引用复用，否则保留history并补当前操作；不重复已有有效测试或昂贵训练。历史96本身不证明96处当前点击。

正常流程缺绑定、值没保存、对象错传、导出为空/元数据当指标、配置过滤残留等真实缺陷由调度在R14原边界最小返修→独立复核→原入口复点。夹具缺真实列/当前输入时先核合成数据的生产链，不伪造结果证明；无旧样本可用受支持真实配置输入造专用样本，但不注入任务/错误内部状态。计划内失败不逐条唤醒总控，不能以失败少见当作忽略理由。
