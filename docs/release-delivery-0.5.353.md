# 0.5.353 每张 GPU 独立配置

0.5.352 仅提供全局及服务器默认值，未满足用户逐卡配置的要求。本次增加 Worker 的 gpuCardOverrides，以实际 GPU 编号为键，每张卡分别覆盖最大并行 job 数及可派发最低总剩余显存 GiB。继承顺序为逐卡、服务器、全局；两个字段可分别留空继承。单卡配额 0 仅暂停后续派发，不停止已有任务。未检测到的卡保留设置，但不会参与派发。

服务器配置区根据本轮实际 GPU 列表生成逐卡输入，并展示剩余显存；已保存但离线的卡仍可编辑。同一服务器 GPU 0、1、2 可以使用不同配额及显存门槛。保存与重载保留独立设置，清空字段回到服务器默认值。GPU 状态和任务活动不修改用户设置。

Host 自动分配、手动派发、可用性和预派发权重均按对应卡计算。完整逐卡策略传到 Agent 和独立 Scheduler，已接收队列使用当前控制窗口策略；更新或降低配额不重建、停止或重跑任务。新 gpuCardQuotaScheduling 能力门禁防止旧 Agent/Scheduler 静默忽略逐卡字段。原 0.5.352 默认值和历史迁移兼容，无逐卡覆盖时行为不变。

验证覆盖异构配额、不同门槛、22 GiB 边界、配额 0、空值继承、未知卡、离线保留、配置规范化、真实渲染表单、实际 Host 自动与手动请求、Agent HTTP 配置和隔离 tmux Scheduler。特别核实：清空逐卡覆盖后，已接收队列不能从原 job 参数带回旧覆盖。隔离 Scheduler 观察到当前空覆盖、默认配额 1 和真实占用 1 时保持最后一个 job 排队；恢复该卡配额 6 后才启动，原运行窗口及身份保留。
