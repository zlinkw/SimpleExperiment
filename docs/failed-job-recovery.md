# 失败 job 召回

分布式 Plan 的失败 job 提供「召回本机重跑」。操作只为该 job 建立新的 attempt，保留 Plan 的运行模式、代码版本以及其他 job 的状态。原 Worker 离线也能完成本机排队；分配继续使用现有的空闲 GPU 与版本校验规则。

确认页面列出原 Worker 的服务器、用户、端口、安全根、源目录与 clean_dir 目标目录。确认后，待处理记录与新 attempt 一起持久化，插件重载后继续处理。原 Worker 恢复并更新到支持 failedAttemptQuarantine 的 Agent 后，插件静默核验完整任务身份、PID、真实 tmux pane 和 SHA256。原任务仍活动时，只停止这个已授权的旧 attempt；新 attempt 不受影响。原任务已经完成、身份无法核实或目录有链接、挂载、跟踪文件时保留原内容。

旧失败目录移入原项目的 clean_dir，保留原始拓扑，并写入 MANIFEST.md。目标不得覆盖。移动前重新检查直接父目录和源内容，移动后核对完整内容摘要；回执丢失时依据持久日志恢复，重复请求不会再次移动。离线或核验失败按退避重试，不弹出重复警告。

这是可恢复的移走操作，不会永久删除文件，也不会释放磁盘空间。永久删除仍需使用现有审核和路径确认流程。所有成功结果与其他版本的目录均保留。

代码验证包括离线召回、三个运行模式、重复点击、队列重载、旧回执隔离、原任务恢复活动、身份与哈希异常、目录冲突、父目录检查以及移动日志恢复。Windows 测试使用有界 POSIX 移动替身，并模拟稳定 POSIX ctime；真实 Worker 的移动验收需在更新 Agent 后进行。
