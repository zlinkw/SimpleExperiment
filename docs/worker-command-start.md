# Worker 命令启动、运行状态与错误摘要

## 0.5.317 修复边界

2026-10-15 只读核对 0.5.316 插件的当前任务窗口，NWPU3 的项目子命令报 `ModuleNotFoundError: No module named 'torch'`，NWPU5 的 run_wrapper 子命令报 `FileNotFoundError: 'python'`。任务窗口确实已建立并以退出码 1 结束。未停止、删除或重跑这些生产任务。

公共 task_shell_args 选择了外层绝对 Python，却没有在登录脚本之后恢复选中环境；run_wrapper 内的裸 `python` 因而依赖系统 PATH。这不是新增依赖检测的理由。修复仅恢复启动时使用用户配置的环境：

- 在登录脚本之后激活选中环境。Conda 可用时加载 shell hook 并执行 conda activate；无 Conda 命令时使用选中解释器的 bin、CONDA_PREFIX 及该环境的 activate.d 脚本。
- 子进程继续继承这一环境。重复包装不依赖旧 tmux 服务的环境；环境脚本执行后重新绑定当前 job 的 GPU 和身份。
- 不执行环境修复、安装、torch/CUDA 导入探针、库哈希或数据集核验。项目命令自身的错误如实返回，不把本次修复等同于已证明生产环境依赖齐全。

原生任务先保留 starting 阶段，完成环境激活后在精确任务窗口中标记 running，随后执行启动命令。排队、准入、环境激活和提交操作不算运行中；未知阶段不能默认运行。退出窗口按实际退出码和产物清单判断，旧状态及提交响应不覆盖当前查询。

PLAN 选择器、后端摘要、工作台和运行进度卡片区分准备提交、排队、正在启动、运行中。后台提交操作的 running 只表示操作正在处理，不得当作 job 正在执行。

失败卡片只显示最多 180 字符的错误摘要，优先选择最后一个异常原因；不展开完整命令、配置、traceback 或终端历史。保留“查看窗口日志”，按原 Worker/commandId 定位对应任务窗口，完整输出仍由原日志入口读取。启动前拒绝且没有窗口的任务，保留对应说明并禁用窗口跳转。

## 验证方式

使用临时环境与模拟 Conda hook，在登录脚本故意重设 PATH 后，由绝对解释器启动子命令 `python`，确认子命令仍属于选中环境；同时验证环境脚本、GPU 与任务身份、原始失败退出码和用户库配置保留。只提取被测函数，不导入完整生产运行时，不启动训练。

生命周期回归覆盖 queued、bound、admitted、starting、running、未知窗口阶段与退出码。渲染回归覆盖长终端输出的精简展示、正确窗口按钮、启动阶段不增加运行数、PLAN 选择器和概览阶段。发行、安装与尚待实机核对的项目另见交付记录。
