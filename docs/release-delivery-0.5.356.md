# 0.5.356 逐任务核实产物与 PLAN 未知状态

现场运行版已为 0.5.355。只读 tasks.list 显示其他 Worker 能返回完整观察，但 H20 仍整批超时，只有 executionOnly 清单；43 个当前窗口中包含退出码 0 的 concatenation_pad_p100 seed 42、43，产物及日志证据没有返回。同步成功提示不能证明当前任务已经核实，查询超时也不能证明产物缺失。0.5.355 只保住执行观察，没有解决产物观察的整批等待，本次补全该链路。

本轮先查询真实窗口，然后以最多四个独立单任务请求查询当前产物和日志；观察入口只读公开身份，不读取分块启动源码。成功结果在本轮内归并，某一任务失败或超时不抹掉其他任务已核实的结果；超时后从下一个任务继续轮转，防止慢任务永久饿死后续查询。保留完整控制查询、清理窗口和提交前保护；部分结果观察不能冒充完整提交检查。断线或重载不恢复结果计算，不新增状态文件，不用上轮产物冒充本轮核实。

原完成校验还将写入端文件的 inode、device、ctime、mtime 与当前节点比较，合法同步复制后的文件因本机属性不同被误判。改为核实当前普通文件、声明路径、runId、模式、job 身份、非空及声明字节数；指标存在 SHA256 声明时主动读取并核对内容，同时检查本次读取期间文件未变化。不扫描权重内容，截断权重和同长度损坏指标仍不能通过。单次日志分析读取有界分块，原有内存游标、异常识别、明确非零退出及异常复核规则保留。

PLAN 列表和前端回退逻辑新增“待核实”，不再把查询未知混为实际“部分完成”。源端有效结果不等待所有副本同步成功；已证实的缺项才作为不完整。保留实际完成数量，不补零、不按退出码 0 或同步回执伪造完成。

回归包含单项失败保留其余五个完成结果、超时保留已核实结果、轮转和晚到响应隔离、完整观察不闪回、同步复制属性变化、同长度指标损坏、权重截断、精确选中任务跳过启动载荷、PLAN 未知/完整/缺项与同步状态解耦。旧 planTerminalStatusRecovery 两处将提交进度直接视为运行中的夹具已修正为现行“准备提交中”，生产运行判定未放宽。

未启动、停止、重跑、删除或覆盖现有科研任务、环境、日志和产物；实际远端验收等待用户重载并通过原入口更新 Agent/Scheduler。

结果观察使用有界普通请求池，保留停止和轻量执行查询的紧急通道。HTTP 分支夹具同时验证普通精确控制查询与只读结果观察参数，避免测试替身遗漏新参数造成假失败。
