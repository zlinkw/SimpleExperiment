# 会话整组关闭与覆盖预览中的硬链接

## 会话整组关闭

其他会话行新增“关闭全部窗口”，不再要求逐个点击标签。点击后由 Host 实时核对服务器、会话、全部 windowId 和 paneId，弹窗列出精确目标，提醒窗口内进程会终止。取消不发送关闭命令。

复用 GPU 卡片的批量关闭协调器和单窗口执行器，按冻结的 windowId 逐项关闭；数字索引重排仍按原身份定位。列表变化、新增窗口、窗口替换或查询失败时停止并报告实际已完成数量，不扩大本次目标。不调用 kill-session、kill-server 或 PID 信号，不删除文件。Agent 会话保留其专用服务管理入口。普通会话由本次明确选择决定，不按 GPU 前缀推断归属。

回归执行真实渲染脚本、按钮点击和 Host 方法，验证整组请求、重复点击、服务器切换、取消、窗口集合变化、逐项进度及 Agent 保护。旧 GPU 入口和单标签关闭保留。

## 为什么运行 PLAN 会出现 cleanup.preview

运行流程会先读取已有产物，为“覆盖并重跑”准备只读预览。SHARED_HARDLINK 在这一阶段来自 SimpleSFTP 对实际文件硬链接数的检查，不证明存在旧协议状态，也不表示已经执行删除。只有用户选择覆盖并完成两次精确路径确认后，才进入删除旧产物与提交新任务。

SimpleSFTP 0.2.87 允许 confirmed_paths 删除中的普通文件具有多个硬链接，仅 unlink 用户确认范围内的名称；保留其他名称及其内容。仍拒绝符号链接、目录链接、越界、类型或 inode 变化，保留安全根、物理直接父目录和最短相对路径。普通移动、恢复和非路径授权流程维持原硬链接限制。

对已核实为硬链接的文件，冻结清单记录硬链接属性，后续核对继续使用同一分类。解除本批另一个名称造成的 inode ctime 变化不会令剩余文件失效；仍核对 device、inode、大小、mtime，实际写入引起这些信息变化仍拒绝。普通文件保留原 ctime 核对。扫描不追查其他硬链接位置，不读取大型权重内容，不新增服务器状态文件。

隔离夹具覆盖同目录多个名称、跨 job 冻结预览、最后一个内部硬链接、保留范围外源文件、内容变化拒绝及普通模式仍拒绝。开发未关闭真实窗口、删除生产产物或重跑任务。
