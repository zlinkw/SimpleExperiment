# 0.5.332 覆盖确认与清理查询修复

## 修复与边界

0.5.331 的两个 AOEPT 覆盖提交记录均报告“工作区或连接已变化，未继续运行”，而现场工作区与面板会话仍相同。生产代码的隧道检测会调用 resetClient 重建客户端对象；PlanRunHost 却用对象引用相等判断确认是否仍有效，因此同一服务器配置下的正常重连也会使第二次确认或后续批次失效。真实 Host 覆盖流程的合成回归重现了相同错误。

覆盖流程现在绑定项目上下文、启用 Worker、服务器、用户、SSH 端口、项目目录、实际 Agent 端点及所选环境，不以客户端对象引用裁决。同配置重建可以继续；真实工作区、连接目标或环境配置变化仍阻止继续。原有 PLAN/代码检查、两次完整路径确认、安全根、类型、指纹及直接父目录保护保留。没有更改删除目标或 SimpleSFTP 删除协议。

失败任务审核还存在两层过早超时：单项查询独立限制为 10 秒，多节点观察又共用一个 10 秒总预算，后面的节点可能未被查询就报告超时。SimpleSFTP 的本机/SSH 清理读取本身有 60 秒边界。本次取消更短的独立竞争与共用预算，将客户端兜底设为 65 秒以容纳底层返回；节点之间最多四组并行，每个节点内串行。查询失败保留未知/未完成，重新查询可恢复，不重复执行删除。真正超时提供服务器、完整路径与接口信息，不再只有裸 CLEANUP_QUERY_TIMEOUT。确认前仍检查实际内容变化；没有减弱文件指纹或路径防护。

对最新失败清理批次进行了只读主动状态查询：返回 ready、目标 pending 且无查询错误。本轮没有因此自动执行、恢复文件或重新提交原任务，也没有把旧清理记录当作文件存在与否的权威。
